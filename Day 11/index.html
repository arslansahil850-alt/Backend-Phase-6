Day 11 Object Storage & Media Delivery

Cloud File Storage

Saving user avatars, PDFs, or videos onto a Node.js server's local filesystem breaks horizontal scaling, gets wiped on container restarts, and saturates Express bandwidth on large transfers. Today you will learn how cloud object storage works, how presigned upload and download URLs offload heavy file bytes, how to validate and isolate untrusted uploads safely, and how CDNs and lifecycle policies optimize cost and speed.

Connection to Days 2 & 8

External object storage keeps API replicas stateless, while server-issued presigned URLs let you enforce strict user ownership before granting temporary read/write access.

Core Principle

Keep buckets private by default, store file metadata in your primary database, validate file content rather than extensions, and let clients transfer bytes directly to object storage.

Practical Output

Implement an S3-compatible presigned upload/download workflow (with a clearly separated local development adapter) and metadata confirmation endpoint.

02. Deep Dive

Core Cloud File Storage Concepts

1. Local Storage vs. Object Storage

Local filesystem storage (./uploads/avatar.png) ties files to a single machine's disk. As covered in Day 2, another container instance cannot read that file, container deployments wipe ephemeral disks, and scaling disk capacity independently is rigid.

Object storage stores immutable blobs ("objects") inside logical containers called buckets, identified by a flat string key such as uploads/tenants/t_9/2026/uuid-invoice.pdf. Slashes in keys simulate folder organization visually, while the store scales horizontally across redundant drives with high durability.

2. Upload and Download Workflows

  • API-Proxied Upload: Client sends multipart/form-data to Express (e.g., via multer memory/stream), Express validates bytes/magic header, and streams to S3. Simple for tiny files (< 2 MB), but ties up Node.js memory/sockets for large files.
  • Direct Presigned Upload: Client asks Express POST /api/files/upload-intent; Express authenticates, checks quota, creates a pending metadata row in DB, and returns a short-lived Presigned PUT URL. The browser uploads bytes directly to object storage, then notifies Express to mark the metadata record ready (or S3 triggers a webhook/queue job).

3. Secure File Access & Signed URLs

Private user documents (invoices, tax PDFs, ID scans) must live in a private bucket with public listing/reading disabled. When an authorized user requests a download (GET /api/files/:id/download), your backend verifies ownership (Day 8) and generates a Presigned GET URL valid for a short window (for example, 60–300 seconds). Anyone holding that signed URL during its brief window can download that specific object without needing AWS credentials.

4. File Metadata in Your Database

Object storage is optimized for retrieving objects by exact key—not searching by owner, status, or page. Store structured metadata in MongoDB or PostgreSQL: fileId, ownerId, objectKey, originalFilename, mimeType, sizeBytes, status (pending | ready | deleted), and optional SHA-256 checksum. Never use user-supplied filenames directly as storage keys—generate random UUID keys!

5. File Size and Type Validation

Never trust file.originalname (malware.exe.png) or the HTTP Content-Type header—clients can forge both trivially.

  • Server-Enforced Size Caps: Reject oversized requests early (in Express stream limits or S3 presigned POST policy content-length-range conditions, plus checking actual stored HeadObject size afterward).
  • Magic-Byte Signature Inspection: Read the leading bytes of the file (for example, PNG starts with 89 50 4E 47, PDF with 25 50 44 46) via libraries like file-type to confirm the true binary format.

6. CDN Basics

A Content Delivery Network (CDN) caches static and public media (product images, avatars, public assets) at geographically distributed edge servers close to users, cutting latency and saving expensive origin object-storage egress fees. Assign immutable versioned keys (e.g., avatars/u_42/v3-a91f.webp) so you can safely set long Cache-Control: public, max-age=31536000, immutable headers without stale-cache headaches.

7. Storage Permissions and Lifecycle Policies

  • Least-Privilege Bucket Policies: Grant the backend IAM role access only to the specific application bucket and required actions (s3:PutObject, s3:GetObject, s3:DeleteObject)—never wildcard admin permissions across all buckets.
  • CORS Configuration: Direct browser uploads require allowing your frontend origin for PUT/POST on the bucket's CORS policy.
  • Lifecycle Policies: Automatically abort incomplete multipart uploads after 1–3 days, delete abandoned pending temp prefixes, or archive old compliance logs to cold storage tiers.

8. Safe Handling of User-Uploaded Files

User-uploaded files are untrusted input:

  • Prevent XSS via SVG/HTML Uploads: Serving a user-uploaded .svg or .html inline from your main app domain (app.example.com/uploads/evil.svg) executes embedded <script> tags with your origin's privileges! Serve user uploads from an isolated sandbox domain (or object-storage CDN domain), enforce Content-Disposition: attachment for downloads, and set X-Content-Type-Options: nosniff.
  • Path Traversal Defense: Always generate UUID object keys on the server; never concatenate req.body.filename (like ../../etc/passwd) into local or bucket paths.
  • Async Malware Scanning & Re-Encoding: For sensitive workflows, quarantine uploads in a staging/ prefix until a background worker (Day 5) scans or re-encodes images (which also strips hidden EXIF GPS metadata).
03. Mechanics

Direct Presigned Upload & Verification Workflow

  1. Request Upload Intent: Browser sends file name, declared MIME type, and byte size to POST /api/files/upload-url.
  2. Server Validates & Signs: Backend verifies authentication, checks allowed MIME/size limits, generates a UUID objectKey, saves a pending metadata record, and returns a 2-minute presigned PUT URL.
  3. Direct Byte Transfer: Browser uploads the file straight to cloud object storage (or local dev storage endpoint), bypassing Node.js RAM completely.
  4. Confirmation & Inspection: Browser calls POST /api/files/:id/confirm; backend calls HeadObject / checks magic bytes to verify size & true file format before flipping status to ready.

05. Step-by-Step Implementation

Controlled File Upload Workflow (Cloud S3 & Local Dev Adapter)

Using Day 1's Dependency Injection pattern, we define a clean S3StorageProvider for production/MinIO and a clearly marked LocalDevStorageProvider for offline local testing—without changing FileService at all!

Part A — Server-Side S3 Provider & Local Development Substitute

Server-Side: src/shared/storage/s3StorageProvider.js 
import {
  S3Client,
  PutObjectCommand,
  GetObjectCommand,
  HeadObjectCommand
} from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

export class S3StorageProvider {
  constructor() {
    this.bucket = process.env.STORAGE_BUCKET;
    this.client = new S3Client({
      region: process.env.STORAGE_REGION || 'us-east-1',
      endpoint: process.env.STORAGE_ENDPOINT || undefined,
      forcePathStyle: Boolean(process.env.STORAGE_ENDPOINT)
    });
  }

  async createPresignedUploadUrl({ key, contentType, expiresInSeconds = 120 }) {
    const command = new PutObjectCommand({
      Bucket: this.bucket,
      Key: key,
      ContentType: contentType
    });
    return getSignedUrl(this.client, command, { expiresIn: expiresInSeconds });
  }

  async createPresignedDownloadUrl({ key, downloadName, expiresInSeconds = 120 }) {
    const safeName = downloadName.replace(/[^a-zA-Z0-9._-]/g, '_');
    const command = new GetObjectCommand({
      Bucket: this.bucket,
      Key: key,
      ResponseContentDisposition: `attachment; filename="${safeName}"`
    });
    return getSignedUrl(this.client, command, { expiresIn: expiresInSeconds });
  }

  async headObject(key) {
    const res = await this.client.send(
      new HeadObjectCommand({ Bucket: this.bucket, Key: key })
    );
    return {
      sizeBytes: Number(res.ContentLength || 0),
      contentType: res.ContentType || ''
    };
  }

  async readFirstBytes(key, byteCount = 16) {
    const res = await this.client.send(
      new GetObjectCommand({
        Bucket: this.bucket,
        Key: key,
        Range: `bytes=0-${byteCount - 1}`
      })
    );
    const chunks = [];
    for await (const chunk of res.Body) {
      chunks.push(chunk);
    }
    return Buffer.concat(chunks);
  }
}
Server-Side (Local Dev Substitute Only): src/shared/storage/localDevStorageProvider.js 
import fs from 'node:fs/promises';
import path from 'node:path';
import crypto from 'node:crypto';

export class LocalDevStorageProvider {
  constructor(baseDir = path.resolve(process.cwd(), '.local_dev_storage')) {
    this.baseDir = baseDir;
  }

  resolveSafePath(key) {
    const normalized = path.normalize(key).replace(/^(\.\.(\/|\\|$))+/, '');
    const target = path.resolve(this.baseDir, normalized);
    if (!target.startsWith(this.baseDir + path.sep)) {
      throw new Error('INVALID_STORAGE_KEY');
    }
    return target;
  }

  signDevToken(key, action, expiresAtMs) {
    const secret = process.env.LOCAL_DEV_SIGNING_KEY || 'dev-only-local-key';
    return crypto
      .createHmac('sha256', secret)
      .update(`${action}:${key}:${expiresAtMs}`)
      .digest('hex');
  }

  async createPresignedUploadUrl({ key, expiresInSeconds = 120 }) {
    const exp = Date.now() + expiresInSeconds * 1000;
    const sig = this.signDevToken(key, 'put', exp);
    return `/api/dev-storage/upload?key=${encodeURIComponent(key)}&exp=${exp}&sig=${sig}`;
  }

  async createPresignedDownloadUrl({ key, expiresInSeconds = 120 }) {
    const exp = Date.now() + expiresInSeconds * 1000;
    const sig = this.signDevToken(key, 'get', exp);
    return `/api/dev-storage/download?key=${encodeURIComponent(key)}&exp=${exp}&sig=${sig}`;
  }

  async headObject(key) {
    const filePath = this.resolveSafePath(key);
    const stats = await fs.stat(filePath);
    return { sizeBytes: stats.size, contentType: 'application/octet-stream' };
  }

  async readFirstBytes(key, byteCount = 16) {
    const filePath = this.resolveSafePath(key);
    const handle = await fs.open(filePath, 'r');
    try {
      const buf = Buffer.alloc(byteCount);
      const { bytesRead } = await handle.read(buf, 0, byteCount, 0);
      return buf.subarray(0, bytesRead);
    } finally {
      await handle.close();
    }
  }
}

Part B — Server-Side FileService with Validation & Magic-Byte Check

Server-Side: src/modules/files/file.service.js 
import crypto from 'node:crypto';
import { AppError } from '../../shared/errors/AppError.js';

const MAX_BYTES = 10 * 1024 * 1024;
const ALLOWED_TYPES = new Set(['image/png', 'image/jpeg', 'image/webp', 'application/pdf']);

function matchesMagicBytes(buf, mimeType) {
  if (mimeType === 'image/png') {
    return buf.length >= 4 && buf[0] === 0x89 && buf[1] === 0x50 && buf[2] === 0x4e && buf[3] === 0x47;
  }
  if (mimeType === 'image/jpeg') {
    return buf.length >= 3 && buf[0] === 0xff && buf[1] === 0xd8 && buf[2] === 0xff;
  }
  if (mimeType === 'application/pdf') {
    return buf.subarray(0, 4).toString('ascii') === '%PDF';
  }
  if (mimeType === 'image/webp') {
    return buf.length >= 12 && buf.subarray(0, 4).toString('ascii') === 'RIFF' && buf.subarray(8, 12).toString('ascii') === 'WEBP';
  }
  return false;
}

export class FileService {
  constructor({ fileRepo, storageProvider }) {
    this.fileRepo = fileRepo;
    this.storage = storageProvider;
  }

  async createUploadIntent({ userId, originalName, mimeType, sizeBytes }) {
    if (!ALLOWED_TYPES.has(mimeType)) {
      throw new AppError('Unsupported file type', 400, 'INVALID_FILE_TYPE');
    }
    if (!Number.isInteger(sizeBytes) || sizeBytes <= 0 || sizeBytes > MAX_BYTES) {
      throw new AppError('File exceeds 10 MB limit', 400, 'INVALID_FILE_SIZE');
    }

    const objectKey = `uploads/${userId}/${crypto.randomUUID()}`;
    const record = await this.fileRepo.create({
      ownerId: userId,
      objectKey,
      originalName: String(originalName).slice(0, 120),
      mimeType,
      declaredSizeBytes: sizeBytes,
      status: 'pending'
    });

    const uploadUrl = await this.storage.createPresignedUploadUrl({
      key: objectKey,
      contentType: mimeType,
      expiresInSeconds: 120
    });

    return { fileId: record._id, uploadUrl };
  }

  async confirmUpload({ fileId, userId }) {
    const file = await this.fileRepo.findById(fileId);
    if (!file) {
      throw new AppError('File record not found', 404, 'FILE_NOT_FOUND');
    }
    if (String(file.ownerId) !== String(userId)) {
      throw new AppError('Forbidden', 403, 'FORBIDDEN');
    }

    const meta = await this.storage.headObject(file.objectKey);
    if (meta.sizeBytes <= 0 || meta.sizeBytes > MAX_BYTES) {
      throw new AppError('Uploaded object violates size limit', 400, 'INVALID_UPLOADED_SIZE');
    }

    const headerBytes = await this.storage.readFirstBytes(file.objectKey, 16);
    if (!matchesMagicBytes(headerBytes, file.mimeType)) {
      throw new AppError('File signature does not match declared type', 400, 'SIGNATURE_MISMATCH');
    }

    return this.fileRepo.markReady(fileId, meta.sizeBytes);
  }

  async getSignedDownload({ fileId, userId }) {
    const file = await this.fileRepo.findById(fileId);
    if (!file || file.status !== 'ready') {
      throw new AppError('File not available', 404, 'FILE_NOT_FOUND');
    }
    if (String(file.ownerId) !== String(userId)) {
      throw new AppError('Forbidden', 403, 'FORBIDDEN');
    }

    const downloadUrl = await this.storage.createPresignedDownloadUrl({
      key: file.objectKey,
      downloadName: file.originalName,
      expiresInSeconds: 120
    });
    return { downloadUrl };
  }
}

Part C — Browser-Side Direct Upload Script

Browser-Side: client/uploadFile.js 
export async function uploadSelectedFile(file, accessToken) {
  const intentRes = await fetch('/api/files/upload-url', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${accessToken}`
    },
    body: JSON.stringify({
      originalName: file.name,
      mimeType: file.type,
      sizeBytes: file.size
    })
  });
  if (!intentRes.ok) {
    throw new Error('Failed to create upload URL');
  }
  const { data } = await intentRes.json();

  const uploadRes = await fetch(data.uploadUrl, {
    method: 'PUT',
    headers: { 'Content-Type': file.type },
    body: file
  });
  if (!uploadRes.ok) {
    throw new Error('Direct storage upload failed');
  }

  const confirmRes = await fetch(`/api/files/${data.fileId}/confirm`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${accessToken}` }
  });
  if (!confirmRes.ok) {
    throw new Error('File verification failed');
  }
  return confirmRes.json();
}

Key Code Sections Explained

  • Server-Generated UUID objectKey: Ignores user filenames for storage paths, eliminating filename collisions and path traversal.
  • readFirstBytes Magic-Byte Check: Verifies actual binary headers inside the uploaded object (e.g., rejecting an .exe or <script> HTML file renamed to photo.png).
  • ResponseContentDisposition: 'attachment; filename="..."': Forces browsers to download private files safely rather than executing them inline inside the browser tab.
  • LocalDevStorageProvider Boundary Check: Normalizes keys and verifies target.startsWith(this.baseDir + path.sep) to prevent directory traversal in local testing.

07. Production Readiness

Common File Handling & Security Mistakes

Mistake 1: Serving User-Uploaded SVGs or HTML Inline on Your Main Domain

Critical XSS Vulnerability: SVG files are XML documents capable of running embedded JavaScript. Serving them inline on app.example.com allows Stored XSS.

Fix: Never allow untrusted SVG/HTML in image allowlists without strict sanitization, serve uploads from an isolated sandbox domain, and use Content-Disposition: attachment + X-Content-Type-Options: nosniff.

Mistake 2: Making the Whole Bucket Public-Read

Privacy leak: Storing invoices or ID documents in a public bucket allows anyone who guesses or leaks a URL to read sensitive files forever.

Fix: Keep buckets private by default; issue short-lived presigned GET URLs only after ownership authorization.

Mistake 3: Never Cleaning Up Abandoned pending Uploads

Cost leak: Users cancel uploads midway or never call /confirm, leaving orphan blobs and incomplete multipart parts billing monthly storage.

Fix: Configure bucket lifecycle rules for incomplete multipart uploads and schedule a cleanup job for stale pending files.

Mistake 4: Trusting Declared Size in Presigned PUT Without Verification

Abuse risk: A client declares sizeBytes: 5000 to get a presigned PUT URL, then uploads a 2 GB file unless enforced by S3 policy conditions or verified immediately afterward.

Fix: Use S3 presigned POST policies with content-length-range or check HeadObject size and delete violations immediately.

10. Active Recall

Short-Answer Review Questions

Files saved onto Container 1's local filesystem are invisible to Containers 2 and 3, causing 404 errors behind a load balancer, and container restarts or deployments wipe ephemeral container storage.

Re-encoding uploaded images into clean WebP/JPEG via Sharp strips embedded EXIF metadata (such as smartphone GPS coordinates and camera serials) and destroys malformed payload chunks or polyglot image exploits.

The bucket's CORS rule must explicitly allow your web application's origin (never * unnecessarily for private workflows), allow PUT (and HEAD/GET if needed), and allow required headers such as Content-Type.

Anyone who obtains a presigned URL (via browser history, logs, or link sharing) can access that specific object until it expires. Keeping TTLs short minimizes the exposure window if a link leaks.

Both MinIO and Cloudflare R2 implement the S3 API protocol. Configuring endpoint, region, and forcePathStyle via environment variables inside an injected StorageProvider lets the exact same Node.js service code run against MinIO locally and S3/R2 in production.

Coding, Debugging & System-Design Challenges

Problem: A local dev endpoint runs res.sendFile(path.join('./uploads', req.query.name)). Explain two vulnerabilities and write a safe replacement.

Reference Solution 
export function safeLocalDownload(baseDir, storedKey, originalName, res) {
  const safeRoot = path.resolve(baseDir);
  const resolved = path.resolve(safeRoot, storedKey);
  if (!resolved.startsWith(safeRoot + path.sep)) {
    return res.status(400).json({ error: 'Invalid path' });
  }
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.download(resolved, path.basename(originalName));
}

Vulnerabilities fixed: (1) Path traversal (../../etc/passwd) blocked via prefix containment check on server-owned storedKey; (2) MIME sniffing & inline script execution mitigated via X-Content-Type-Options: nosniff and res.download (Content-Disposition: attachment).

Problem: Unlike PutObjectCommand signed URLs, S3 createPresignedPost lets S3 itself reject oversized uploads mid-stream before storing them. Write a small function using @aws-sdk/s3-presigned-post capping uploads between 1 byte and 5 MB with fixed MIME type.

Reference Solution 
import { createPresignedPost } from '@aws-sdk/s3-presigned-post';

export async function createBoundedUploadPost(s3Client, { bucket, key, contentType }) {
  return createPresignedPost(s3Client, {
    Bucket: bucket,
    Key: key,
    Expires: 120,
    Conditions: [
      ['content-length-range', 1, 5 * 1024 * 1024],
      ['eq', '$Content-Type', contentType]
    ],
    Fields: {
      'Content-Type': contentType
    }
  });
}

Problem: Users upload profile avatars and PDF attachments. Design an end-to-end architecture combining Days 5, 6, and 11 so uploads never expose unscanned files, scale effortlessly, and clean up failed uploads.

Reference Architecture: Client uploads via presigned URL into a private quarantine/ bucket prefix (status: 'pending'). S3 object-created event (or confirm API) enqueues a background job (Day 5/6). A worker validates magic bytes, scans/re-encodes images into clean WebP (stripping EXIF), writes the safe derivative to a public CDN-backed media/ prefix under an immutable key, updates DB metadata to ready, and notifies the client via WebSocket (Day 7). A 24-hour bucket lifecycle rule purges unprocessed quarantine/ objects automatically.

12. Takeaways

Day 11 Revision Summary

  • Object storage decouples files from ephemeral compute nodes and preserves stateless horizontal scaling.
  • Presigned URLs offload upload/download byte transfers directly between clients and storage while keeping buckets private.
  • Metadata & validation live in your backend: store ownership/keys in DB, generate UUID keys, enforce size limits, and verify magic bytes.
  • Defensive headers & isolation protect against Stored XSS (Content-Disposition: attachment, nosniff, isolated media origins).
  • CDNs & lifecycle policies accelerate public reads with immutable keys and prune orphaned/temporary storage automatically.
