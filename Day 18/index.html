01. Curriculum Synthesis

Complete Summaries of Days 1–17

Day 1: Architecture & Design Patterns

Separate routes/controllers (HTTP), services (business rules), and repositories (data queries) using constructor Dependency Injection and SOLID boundaries inside a modular monolith.

Day 2: Scalable Backend Systems

Scale horizontally with stateless instances behind L4/L7 load balancers, move sessions/limits/files to shared Redis and object storage, size DB pools across replicas, and handle SIGTERM cleanly.

Day 3: Performance Optimization

Measure p95/p99 and event-loop lag first; eliminate sync blocking, ReDoS regexes, and N+1 waterfalls; project fields with .lean(), clamp cursor pagination, and compress payloads.

Day 4: Caching with Redis

Apply Cache-Aside with canonical versioned keys, user scoping for private data, jittered TTLs, fail-open fallbacks, and write-then-delete invalidation without blocking KEYS * scans.

Day 5: Background Jobs & Scheduling

Offload slow work via BullMQ queues returning 202 Accepted, separate worker processes, centralize cron schedules, configure exponential backoff, and guard side effects with idempotency.

Day 6: Message Queues & Events

Decouple services via brokers, topic pub/sub fan-out, and competing consumers; combine at-least-once delivery with idempotent consumers, prefetch backpressure, DLQs, and Transactional Outbox.

Day 7: Real-Time WebSockets

Upgrade HTTP to persistent wss:// via 101, authenticate handshakes securely, authorize room joins server-side, track multi-tab presence in Redis, and scale nodes with Redis Pub/Sub adapters.

Day 8: Advanced Auth & Authorization

Pair short-lived JWT access tokens with rotated SHA-256-hashed HttpOnly refresh cookies and reuse detection; combine RBAC permissions with strict resource ownership checks to stop IDOR.

Day 9: API Design & Versioning

Keep REST contracts predictable, allowlist filters/sorts, document via OpenAPI, isolate breaking changes behind versioned DTO adapters with Deprecation/Sunset headers, and weigh GraphQL trade-offs.

Day 10: Database Optimization

Build compound indexes using the ESR rule (Equality, Sort, Range), verify IXSCAN with explain plans, use atomic single-doc ops or short ACID transactions, keep arrays bounded, and choose SQL when relational integrity dominates.

Day 11: Cloud File Storage

Use private object storage buckets, server-generated UUID keys, direct presigned upload/download URLs, magic-byte validation, isolated domains/headers against SVG XSS, CDNs, and lifecycle rules.

Day 12: Logging, Monitoring & Errors

Emit redacted JSON logs to stdout with AsyncLocalStorage correlation IDs, separate /health liveness from timeout-bounded /ready probes, track Golden Signals, and alert on SLO symptoms.

Day 13: Advanced Backend Testing

Combine fast DI unit tests with Supertest + isolated real test DB integration tests, stub external third-party gateways, assert 401/403/IDOR/concurrency cases, and close handles cleanly.

Day 14: Rate Limiting & API Security

Apply threat modeling, distributed Redis sliding/token-bucket limiters, strict Zod schemas against mass assignment/injection, Helmet + CORS allowlists, parameterized queries, and DNS-checked SSRF guards.

Day 15: Docker & Containerization

Build minimal multi-stage non-root images with .dockerignore, cached npm ci --omit=dev, exec-form CMD, runtime-injected secrets, and Compose healthchecked networks + named volumes.

Day 16: CI/CD & Deployment

Gate merges with ephemeral-DB CI tests and audits, build immutable SHA-tagged images, isolate staging/prod secrets, run Expand-and-Contract migrations, and deploy with rolling/blue-green/canary readiness checks.

Day 17: Production Architecture

Unify all layers with timeouts, idempotent jittered retries, circuit breakers, graceful degradation, PITR RPO/RTO recovery drills, ADRs, incident runbooks, and readiness checklists.

02. Reference Glossary

Key Backend Terms & Definitions

Modular MonolithSingle deployable application partitioned into strict domain modules communicating via explicit interfaces.
Stateless ServiceCompute instance holding zero per-client state in local RAM or disk between requests.
Little's LawConcurrency = Arrival Rate × Average Latency; cutting latency directly lowers concurrent resource load.
Cache-AsideApp checks Redis first, queries DB on miss, caches with TTL, and deletes cache key on writes.
Cache StampedeBurst of concurrent cache misses hitting the DB simultaneously when a hot key expires.
IdempotencyProperty ensuring executing an operation repeatedly produces the same server state as executing it once.
Dead-Letter Queue (DLQ)Isolation queue holding poison-pill or retry-exhausted messages without blocking healthy traffic.
Transactional OutboxPersisting domain changes and outgoing event records inside the same atomic DB transaction.
BOLA / IDORAuthorization flaw allowing authenticated users to access other users' records by altering object IDs.
Refresh Token RotationInvalidating each refresh token on use and revoking the entire session family if reuse is detected.
ESR RuleCompound index ordering rule: Equality filters first, Sort fields second, Range predicates last.
Presigned URLTime-limited cryptographically signed URL granting direct upload or download access to one private object.
Correlation IDTrace identifier propagated across HTTP requests, background workers, and event consumers.
SSRFVulnerability where an attacker tricks the server into making HTTP requests to internal or metadata IPs.
Expand-and-ContractMulti-step zero-downtime schema migration adding new fields compatibly before dropping legacy ones.
Circuit BreakerResilience state machine (Closed/Open/Half-Open) failing fast when an upstream dependency stays unhealthy.
RPO / RTOMaximum tolerable data loss window (RPO) and maximum acceptable recovery downtime (RTO).
ADRArchitecture Decision Record capturing context, alternatives, and trade-offs behind a system choice.

04. Trade-Off Matrices

Key Concept Comparison Tables

1. Communication & Async Patterns

Mechanism Best For Guarantee / Ordering Key Limitation
Synchronous REST Immediate validation, CRUD, login Caller receives immediate result/error Coupled to slowest downstream call
Background Job Queue (BullMQ) Offloading slow tasks (email, PDF) At-least-once + retries/backoff Eventual completion; requires worker fleet
Event Broker (RabbitMQ / Kafka) Multi-service pub/sub fan-out Broker-routed durable streams/queues Eventual consistency + broker operations
WebSockets / SSE Live client push & presence Real-time low-latency delivery Requires Redis Pub/Sub adapter to scale

2. Persistence & Storage Choices

Store Primary Strength Ideal Workload Anti-Pattern
PostgreSQL (SQL) ACID transactions, foreign keys, joins Financial ledgers, billing, complex relations Massive binary file blobs
MongoDB Flexible documents, fast nested reads Catalogs, CMS, bounded sub-documents Unbounded growing arrays (>16 MB)
Redis Sub-ms in-memory structures & TTL Caching, rate limits, sessions, queues Irreplaceable durable source of truth with eviction
Object Storage (S3/R2) Cheap durable blob storage + CDN Images, PDFs, videos via presigned URLs Searching/filtering file metadata without a DB

3. Auth & Deployment Trade-Offs

Area Option A Option B Decision Rule
Auth Tokens Stateful Redis Session Cookie Short JWT + Rotated Refresh Cookie Use Redis sessions for pure browser dashboards; JWT + refresh for multi-client APIs
API Evolution Additive changes in v1 New /api/v2 DTO adapter Keep optional additions in v1; version breaking renames/removals behind v2
Deployment Rolling Update Blue-Green / Canary Rolling for standard stateless updates; Blue-Green/Canary when fast cutover or low blast radius is critical
05. Diagnostics

Common Mistakes & Production Troubleshooting Notes

Symptom Likely Root Cause Verified Fix
Users randomly logged out or avatars 404 after scaling to 3 containers In-memory sessions or local disk uploads on single instance Move sessions to Redis, files to S3 object storage
High p99 latency with low CPU (<20%) DB pool saturation, missing timeout, or slow external API Add timeouts, check explain plans, size pools across replicas
All API routes freeze for 300ms simultaneously Event-loop blocked (*Sync call, ReDoS, huge JSON) Profile with monitorEventLoopDelay, move CPU work to workers
Rate limiter blocks every user simultaneously behind proxy Missing trust proxy; all users share LB IP Configure app.set('trust proxy', 1) + Redis limiter
DB errors surge during rolling deployment Destructive migration broke live v1 containers Use Expand-and-Contract migrations across two releases
Worker duplicates emails or charges on crash Missing idempotency under at-least-once delivery Use deterministic jobId + atomic DB status claim

07. Active Recall

20 Short-Answer Review Questions

Keeping services transport-agnostic lets workers, CLIs, and unit tests reuse them; keeping queries in repositories isolates persistence changes and allows swapping in-memory fakes during tests.

Each replica maintains isolated memory, breaking user sessions when load balancers rotate instances and multiplying allowed rate limits by 4x until shared Redis is used.

Averages mask severe tail spikes experienced by the slowest 1–5% of requests caused by GC pauses, lock contention, or pool queuing.

Seeing whether an extra item exists proves hasMore accurately without executing a costly separate total count scan.

TTL jitter prevents synchronized mass key expirations (cache stampede); short-TTL negative sentinels absorb repeated misses for non-existent IDs (cache penetration).

Process crashes, container restarts, or deploys kill in-memory promises silently with zero persistence, retries, or backoff.

Competing consumers share one queue so each message runs once across scaled workers; pub/sub routes copies to separate queues so multiple independent domains react to one event.

Dynamic auth callbacks read the freshest refreshed access token on reconnect, and REST catch-up fetches persisted notifications missed while offline.

RBAC assigns user roles; permission checks verify capabilities (e.g., orders:edit); ownership checks confirm the caller owns or belongs to that specific target record (stopping IDOR).

High-entropy refresh tokens resist brute force, and storing SHA-256 hashes ensures read-only DB leaks do not grant attackers live impersonation tokens.

Adding optional fields or new endpoints is backward-compatible in v1; renaming/removing fields, changing types, or adding mandatory inputs breaks clients and requires v2.

The query lacks a selective matching index (likely doing a COLLSCAN or poorly ordered compound scan) and needs an ESR-aligned index.

Unbounded growth causes expensive disk document reallocation, bloats network reads, and eventually fails at MongoDB's 16 MB limit.

It prevents browsers from executing malicious inline HTML/SVG scripts inside your main application origin (Stored XSS).

Raw IDs create unbounded cardinality metric series that exhaust monitoring memory and fragment latency dashboards.

A misconfigured environment variable could otherwise run deleteMany({}) against a shared development or production database.

Password hashing (Argon2/bcrypt) is CPU/memory-heavy; rate limiting first rejects brute-force floods cheaply before exhausting worker threads.

Each container has its own loopback network namespace; use the Compose service name (e.g., mongo or postgres) over the bridge network.

OIDC mints ephemeral workflow-scoped credentials per run, eliminating permanent static keys stored inside CI secrets.

Degrade gracefully on optional enrichments (recommendations, read cache fallback); always fail closed on authentication, authorization, and payment integrity gates.

08. Applied Mastery

12 Practical Coding, Debugging & Design Challenges

Task: Separate a route handler mixing Joi/Zod check, CouponModel.findOne, discount math, and res.json into Controller + Service + Repository.

Reference Solution: Validate body via route middleware; Controller extracts DTO and calls couponService.applyCoupon({ code, totalCents }); Service calls injected couponRepo.findActiveByCode(code), throws AppError(404/409) on invalid state, and returns integer discounted cents.

Task: Spot and fix 4 scaling blockers: local const rateMap = new Map(), fs.writeFile('./uploads/...'), unpooled DB connect per request, and setInterval invoice cleanup inside app.js.

Reference Solution: Replace local rate map with Redis sliding limiter + trust proxy: 1; move uploads to presigned S3 object storage; create one shared pooled DB client at startup; extract setInterval to a centralized BullMQ repeatable scheduler.

Task: Fix const posts = await Post.find(); followed by for (const p of posts) p.author = await User.findById(p.authorId);.

Reference Fix
const limit = Math.min(Number(req.query.limit) || 20, 50);
const posts = await Post.find(cursor ? { _id: { $lt: cursor } } : {})
  .select('_id title authorId createdAt')
  .sort({ _id: -1 })
  .limit(limit + 1)
  .lean();
const ids = [...new Set(posts.slice(0, limit).map((p) => String(p.authorId)))];
const users = await User.find({ _id: { $in: ids } }).select('_id name').lean();

Task: Invalidate dozens of filtered catalog list cache keys cleanly on product edit without KEYS *.

Reference Solution: Read integer epoch = await redis.get('epoch:catalog') || 1, embed it into list keys (v1:catalog:e${epoch}:cat=...), and execute atomic await redis.incr('epoch:catalog') whenever any product mutates. Old keys expire naturally via TTL.

Task: Prevent a BullMQ email job from retrying 4 times when the user record was deleted, and prevent duplicate sends on retry.

Reference Solution: Throw UnrecoverableError if user/record is missing; perform an atomic conditional DB claim (status: 'pending' → 'sending' or check sentAt) and pass provider idempotency keys.

Task: An order.cancelled (v2) event arrives before delayed order.confirmed (v1). Write an atomic update guard.

Reference Solution: Store lastEventVersion on the projection and run findOneAndUpdate({ _id: orderId, lastEventVersion: { $lt: event.version } }, { $set: { status: event.status, lastEventVersion: event.version } }).

Task: Fix socket.on('join', (room) => socket.join(room)) on a 3-node cluster.

Reference Solution: Verify JWT inside io.use() to set socket.data.userId, verify DB workspace membership inside project:subscribe before calling socket.join(), and attach @socket.io/redis-adapter across all 3 instances.

Task: An endpoint checks requirePermission('reports:read') and runs Report.findById(req.params.id). Explain the flaw and patch it.

Reference Solution: Add tenant and ownership scoping directly in the query/policy: Report.findOne({ _id: req.params.id, tenantId: req.user.tenantId }) plus verifying owner or elevated reports:read:any permission.

Task: Fix pool.query("SELECT * FROM orders WHERE status = '" + req.query.status + "'") and an aggregation putting $lookup before $match.

Reference Solution: Replace SQL string concatenation with parameterized pool.query('SELECT id, total_cents FROM orders WHERE status = $1 LIMIT 50', [validatedStatus]); move $match + $sort + $limit to the start of the aggregation pipeline ahead of $lookup.

Task: Outline defensive checks for user avatar upload + user webhook URL registration.

Reference Solution: Upload via presigned URL with UUID keys, verify size via HeadObject and binary magic bytes (rejecting SVG/HTML), serve via isolated CDN; validate webhook URLs as https:, resolve DNS blocking RFC1918/loopback/169.254.169.254, and set redirect: 'error'.

Task: Ensure tests assert 401/403 IDOR failures and logs never print Bearer tokens.

Reference Solution: Configure Pino redact: ['req.headers.authorization', 'req.headers.cookie', '*.password'] with AsyncLocalStorage requestId; write Supertest cases asserting missing token returns 401 and cross-user mutation returns 403 against an isolated test DB.

Task: Combine Dockerfile, Expand-Contract, and Circuit Breaker for a reliable release.

Reference Solution: Multi-stage non-root Dockerfile with exec-form CMD + SIGTERM drain; CI runs npm ci + ephemeral DB/Redis tests and tags :sha-...; schema changes use Expand-and-Contract; deploy gates traffic on /ready while circuit breakers + timeouts guard external HTTP dependencies.

09. Systems Integration

3 Integrated Backend Case Studies

Case Study 1: Multi-Tenant SaaS Invoicing & Real-Time Workspace Platform

Scenario: Organizations create invoices, generate downloadable PDF receipts, receive payment gateway webhooks, and see instant dashboard status updates across multiple open team tabs.

Integrated Architecture: Modular monolith Express API behind TLS load balancer → PostgreSQL (relational ledger ACID transactions + tenant-scoped queries + PITR backups) → Redis (Cache-Aside permissions, sliding rate limits, BullMQ queues, Socket.IO Redis Adapter) → Private S3 bucket (PDF receipts accessed via 120s presigned GET URLs with Content-Disposition: attachment) → Dedicated worker fleet generating PDFs idempotently and emitting invoice:paid via @socket.io/redis-emitter. Security enforces strict tenant ownership on every query and HMAC signature verification on webhooks.

Case Study 2: High-Traffic Flash-Sale E-Commerce Checkout

Scenario: Product pages receive 5,000 read req/sec while 400 concurrent buyers compete for limited inventory during a 10-minute flash sale.

Integrated Architecture: CDN + Redis Cache-Aside (with TTL jitter + single-flight coalescing) absorbs 95% of catalog reads, keeping DB load low. Checkout bypasses cache and executes atomic conditional inventory deduction (WHERE id = $1 AND stock >= $2) inside a short DB transaction alongside an Outbox OrderPlaced row, protected by client Idempotency-Key headers. Outbox relay publishes to RabbitMQ/Redis Streams so Email, Loyalty, and Analytics consumers process asynchronously with DLQs—keeping checkout p99 latency under 120ms without overselling.

Case Study 3: Secure Document Upload & Webhook Automation Service

Scenario: Users upload 20 MB compliance PDFs/images and configure HTTPS webhooks to notify external partners whenever document processing finishes.

Integrated Architecture: Express issues short-lived presigned PUT URLs into a quarantine/ bucket prefix (saving Node RAM). Confirmation/storage event triggers a BullMQ worker that verifies size via HeadObject, validates binary magic bytes, strips image EXIF via re-encoding, and moves approved assets to ready/. Outbound webhook delivery runs in an isolated worker queue enforcing HTTPS + DNS-resolved non-private IP SSRF checks, redirect: 'error', 3s timeouts, circuit breakers per customer endpoint, and exponential retries before DLQ isolation.
